# Markdown 所见即所得（WYSIWYG）编辑器产品需求文档（PRD）

文档版本：V1.0　｜　日期：2026-10-26　｜　状态：评审稿

> 一句话目标：让用户用 Markdown 的键盘效率写作，同时在编辑过程中实时看到最终排版效果，无需在“源码”与“预览”之间来回切换，且文件始终保持标准、可移植的 Markdown 格式。

## 1. 文档概述

### 1.1 背景

Markdown 因语法简洁、纯文本、易于版本管理而被广泛用于技术文档、知识库、博客与笔记。但传统“左写右看”的双栏模式要求用户在脑中转换语法与效果，注意力被割裂；而纯富文本编辑器又常常牺牲 Markdown 的快捷输入与文件可移植性。市场上 Typora、Notion、飞书文档、Obsidian（Live Preview）等产品已验证“即时渲染”的价值，本产品聚焦于在保持 Markdown 数据本质的前提下提供一致、流畅、可协作的所见即所得体验。

### 1.2 产品目标

1. **所见即所得**：输入语法后即时转化为排版效果，编辑区即最终效果。
2. **键盘优先**：支持 Markdown 输入规则、斜杠命令与快捷键，双手不离键盘即可完成排版。
3. **数据保真**：文档存储为标准 Markdown（CommonMark + GFM + 约定扩展），导入再导出内容不丢失、不被无故改写。
4. **可切换**：随时在 WYSIWYG 与源码模式之间无损切换。
5. **可扩展**：支持公式、图表、脚注等扩展语法及插件机制。

### 1.3 范围

- 范围内：编辑器核心、Markdown 语法支持、交互规则、导入导出、图片与附件、查找替换、主题与排版、性能与无障碍、基础协同与版本。
- 范围外：云端账号体系、权限与企业管理后台、AI 写作（作为后续迭代预留接口）、移动端原生编辑器（本期以响应式 Web 为主）。

### 1.4 术语

| 术语 | 含义 |
| --- | --- |
| WYSIWYG | What You See Is What You Get，所见即所得 |
| 即时渲染（Instant Rendering） | 输入语法标记后立即转化为渲染效果，光标所在块可临时显示语法标记 |
| 块（Block） | 段落、标题、列表、代码块、引用、表格等块级元素 |
| 行内（Inline） | 加粗、斜体、链接、行内代码等行内元素 |
| AST | 抽象语法树，文档在内存中的结构化表示 |
| 往返保真（Round-trip） | Markdown → 编辑模型 → Markdown 后内容语义与尽可能的格式一致 |
| GFM | GitHub Flavored Markdown，含表格、任务列表、删除线等扩展 |

## 2. 用户与场景

### 2.1 目标用户

| 用户 | 诉求 | 典型场景 |
| --- | --- | --- |
| 开发者/技术写作者 | 熟悉语法、追求效率、代码块与图表友好 | README、技术博客、API 文档 |
| 产品/运营 | 少学语法、所见即所得、能插入图片与表格 | PRD、周报、运营文案 |
| 学生/研究者 | 公式、脚注、目录、导出 PDF | 论文笔记、课程笔记 |
| 知识管理者 | 双链、搜索、大量文档管理 | 个人知识库、团队 Wiki |
| 协作团队 | 多人同时编辑、评论、版本回溯 | 团队文档共创 |

### 2.2 核心用户故事

1. 作为写作者，我输入“# ”后希望文字立即变为一级标题，以便不打断写作节奏。
2. 作为写作者，我选中文字后按 Ctrl/Cmd+B 加粗，并在编辑区直接看到效果。
3. 作为开发者，我输入三个反引号加语言名后获得带语法高亮的代码块，并可一键复制。
4. 作为运营，我粘贴网页或 Word 内容时，希望自动转换成干净的 Markdown 结构。
5. 作为作者，我拖入一张图片后希望自动上传/保存并插入图片语法，同时可拖拽调整大小。
6. 作为高级用户，我需要随时切换到源码模式，修改后切回仍保持格式正确。
7. 作为协作者，我希望看到他人光标与修改，并能对选中文字发表评论。

## 3. 竞品与差异化

| 产品 | 所见即所得方式 | 优势 | 不足/机会 |
| --- | --- | --- | --- |
| Typora | 单窗口即时渲染，光标处显示语法 | 体验极简流畅、导出丰富 | 协作能力弱，闭源扩展有限 |
| Obsidian（Live Preview） | 编辑时按行/块即时渲染 | 本地优先、插件生态、双链 | 渲染与源码混合偶有错位，协作需额外服务 |
| Notion | 块编辑器，Markdown 快捷输入 | 块与数据库能力强 | 导出 Markdown 保真度有限，数据非纯文本 |
| 飞书文档/语雀 | 富文本块编辑 + Markdown 快捷输入 | 协作成熟、生态完整 | 数据模型非原生 Markdown |
| 双栏编辑器（如 VS Code 预览） | 左写右看 | 源码控制力强 | 非真正的所见即所得 |

**差异化定位**：以“原生 Markdown 数据 + 即时渲染编辑 + 实时协作”为核心，既保持文件可迁移，又提供接近 Notion/飞书的编辑体验。

## 4. Markdown 语法与特性梳理

### 4.1 语法支持清单

优先级：P0 = 必须；P1 = 重要；P2 = 增强。

| 类别 | 语法元素 | Markdown 写法示例 | 渲染效果 | 优先级 |
| --- | --- | --- | --- | --- |
| 标题 | ATX 标题 1–6 级 | `# 标题` | 对应级别标题 | P0 |
| 标题 | Setext 标题 | 文字下一行 `===` / `---` | 一/二级标题 | P1 |
| 段落与换行 | 段落、软换行、硬换行 | 空行分段；行尾两个空格或 `\` | 段落/换行 | P0 |
| 强调 | 加粗、斜体、加粗斜体 | `**粗**` `*斜*` `***粗斜***` | 对应样式 | P0 |
| 强调 | 删除线（GFM） | `~~删除~~` | 删除线 | P0 |
| 行内代码 | 反引号 | `` `code` `` | 等宽底色 | P0 |
| 链接 | 行内、引用式、自动链接 | `[文字](url)` `<url>` | 可点击链接 | P0 |
| 图片 | 行内与引用式 | `![alt](src "title")` | 图片展示 | P0 |
| 引用 | 块引用（可嵌套） | `> 引用` | 左侧竖线引用块 | P0 |
| 列表 | 无序、有序、嵌套 | ` -  ` ` 1.  ` | 项目符号/编号 | P0 |
| 列表 | 任务列表（GFM） | `- [ ]` `- [x]` | 可点击复选框 | P0 |
| 代码块 | 围栏代码块、语言标识 | ```` ```js ```` | 语法高亮 | P0 |
| 分隔线 | 水平线 | `---` `***` | 水平分隔线 | P0 |
| 表格（GFM） | 表头、对齐、单元格 | `\| a \| b \|` | 可编辑表格 | P0 |
| 转义 | 反斜杠转义 | `\*` | 显示字面字符 | P0 |
| HTML | 行内与块级 HTML | `<kbd>Ctrl</kbd>` | 白名单渲染 | P1 |
| 脚注 | 脚注引用与定义 | `[^1]` | 上标引用与底部注释 | P1 |
| 数学公式 | 行内与块级 LaTeX | `$E=mc^2$` `$$...$$` | 公式渲染 | P1 |
| 图表 | Mermaid 代码块 | ```` ```mermaid ```` | 流程图/时序图 | P1 |
| 目录 | TOC 标记或侧边栏大纲 | `[TOC]` | 文档目录 | P1 |
| Front Matter | YAML 头信息 | `---` 包裹 | 属性面板/折叠块 | P1 |
| 高亮/上下标 | 扩展语法 | `==高亮==` `H~2~O` `x^2^` | 对应样式 | P2 |
| 提示块 | Callout / 容器 | `> [!NOTE]` 或 `:::tip` | 彩色提示块 | P2 |
| 双向链接 | Wiki 链接 | `[[页面名]]` | 内部跳转 | P2 |
| 表情 | Emoji 短代码 | `:smile:` | 表情符号 | P2 |

### 4.2 规范约定

- 以 **CommonMark** 为基线，叠加 **GFM** 扩展；其余扩展（公式、脚注、Callout 等）以显式开关管理，并在导出时可降级为标准写法。
- 解析歧义统一遵循 CommonMark 规范测试集；对不识别的语法**原样保留**，不得删除或静默改写。

## 5. 所见即所得交互设计

### 5.1 编辑模式

| 模式 | 说明 | 适用 |
| --- | --- | --- |
| 即时渲染模式（默认） | 全文渲染为最终效果；光标进入某个块/行内元素时，临时显示该元素的语法标记（如 `**`），离开后恢复渲染 | 日常写作 |
| 源码模式 | 显示纯 Markdown 文本，带语法高亮、行号 | 精确控制、排错 |
| 分栏预览模式（可选） | 左源码右预览，滚动同步 | 习惯双栏的用户 |

三种模式共用同一份文档数据，切换时保持光标位置、滚动位置与撤销历史。

### 5.2 输入规则（Input Rules）

| 触发输入 | 转换结果 | 撤销行为 |
| --- | --- | --- |
| 行首 `#`\~`######` + 空格 | 对应级别标题 | 紧接着按退格恢复为原始字符 |
| 行首 `-`、`*`、`+` + 空格 | 无序列表 | 退格恢复 |
| 行首 `1.` + 空格 | 有序列表（保留起始编号） | 退格恢复 |
| 行首 `[ ]` 或 `- [ ]` | 任务列表 | 退格恢复 |
| 行首 `>` + 空格 | 引用块 | 退格恢复 |
| 行首 \`\`\` + 语言名 + 回车 | 代码块 | 退格恢复 |
| 行首 `---` + 回车 | 分隔线 | Ctrl/Cmd+Z 恢复 |
| `**文字**`、`*文字*`、`~~文字~~`、`` `文字` `` | 加粗/斜体/删除线/行内代码 | 紧接着 Ctrl/Cmd+Z 恢复为语法文本 |
| `[文字](url)` | 链接 | 同上 |
| `$公式$` | 行内公式 | 同上 |

> 规则：输入规则转换后的第一次撤销应当“还原为用户输入的原始字符”，而非直接回退整个操作，以符合 Markdown 用户心智。

### 5.3 光标与语法标记显示

1. 光标进入行内元素（如加粗、链接、行内代码）时，在该元素两端显示淡色语法标记；离开后隐藏。
2. 光标进入块级元素（如标题）时，可在行首显示 `#` 标记；离开后隐藏。
3. 标记的显示与隐藏不得引起文本抖动（布局偏移应尽量小），并保持光标不跳动。
4. 用户可在设置中选择：始终隐藏、光标处显示（默认）、始终显示。

### 5.4 快捷键与命令

| 操作 | Windows / Linux | macOS |
| --- | --- | --- |
| 加粗 / 斜体 | Ctrl+B / Ctrl+I | Cmd+B / Cmd+I |
| 删除线 | Ctrl+Shift+X | Cmd+Shift+X |
| 行内代码 | Ctrl+E | Cmd+E |
| 插入链接 | Ctrl+K | Cmd+K |
| 标题 1–6 | Ctrl+1 \~ 6 | Cmd+1 \~ 6 |
| 有序/无序列表 | Ctrl+Shift+7 / 8 | Cmd+Shift+7 / 8 |
| 任务列表 | Ctrl+Shift+9 | Cmd+Shift+9 |
| 引用 | Ctrl+Shift+B | Cmd+Shift+B |
| 代码块 | Ctrl+Shift+C | Cmd+Option+C |
| 切换源码模式 | Ctrl+/ | Cmd+/ |
| 查找 / 替换 | Ctrl+F / Ctrl+H | Cmd+F / Cmd+Option+F |

快捷键支持用户自定义，并避免与浏览器及系统快捷键冲突。

### 5.5 斜杠命令与浮动工具栏

- **斜杠菜单**：在空行或行首输入 `/` 弹出命令面板，支持拼音与关键字模糊搜索（标题、列表、表格、代码块、图片、公式、图表、分隔线、提示块等）。
- **浮动工具栏**：选中文本后出现，提供加粗、斜体、删除线、代码、链接、标题级别、高亮、清除格式。
- **块手柄**：悬停块左侧显示拖拽手柄与“+”按钮，支持块的拖拽排序、复制、删除、转换类型。

| CO-03 | 版本历史、差异对比（Markdown 源码级与渲染级）、一键恢复 | P1 |
| CO-04 | 自动保存与离线编辑，联网后合并 | P0 |
| CO-05 | 冲突处理策略：块级合并优先，无法自动合并时提示用户 | P1 |

## 7. 技术方案要点

### 7.1 总体架构

```
Markdown 文本
   │ 解析（CommonMark/GFM + 扩展）
   ▼
  AST（mdast）
   │ 转换
   ▼
编辑器文档模型（Schema：块 / 行内 / 标记）
   │ 渲染                        ▲ 用户输入 / 命令 / 协同操作
   ▼                             │
 视图层（contenteditable / 自绘） ┘
   │ 序列化（保留风格、保真）
   ▼
Markdown 文本（保存 / 导出）
```

### 7.2 关键设计决策

| 议题 | 方案建议 | 说明 |
| --- | --- | --- |
| 编辑内核 | 基于成熟框架（如 ProseMirror/Tiptap、Lexical、Slate 之一）构建 | 评估标准：IME 稳定性、协同支持、插件生态、性能 |
| 解析器 | 使用 remark/mdast 或 markdown-it，遵循 CommonMark 规范 | 扩展语法通过插件接入 |
| 数据真源 | 以结构化文档模型为运行时真源，Markdown 为持久化与交换格式 | 保存时序列化，打开时解析 |
| 往返保真 | 记录原始风格（列表符号、强调符号、缩进、换行），序列化时尽量还原；未编辑区域保持原文 | 降低“无意修改”引发的版本噪声 |
| 光标映射 | 维护“源码偏移 ⇄ 文档模型位置”的映射，保证模式切换光标不丢 | 源码模式与即时渲染共享选区 |
| 安全 | HTML 白名单净化（如 DOMPurify），禁用脚本与危险属性；链接限制协议 | 防止 XSS |
| 性能 | 大文档虚拟化渲染、增量解析、重型组件（公式、图表、高亮）懒加载 | 见非功能指标 |
| 协同 | 文档模型层使用 CRDT（如 Yjs）或 OT，并映射为 Markdown 差异 | 保证离线合并 |

### 7.3 往返保真测试策略

1. 使用 CommonMark 官方规范用例与 GFM 用例做解析一致性测试。
2. 构造“Markdown → 模型 → Markdown”往返测试集，统计语义等价率与文本字面一致率。
3. 引入真实文档语料（README、技术博客、飞书/Notion 导出）做回归。
4. 对模糊场景（嵌套、转义、空行、混合缩进）建立专项用例库。

## 10. 测试与验收

1. **功能测试**：覆盖第 6 章全部 P0/P1 需求，每条需求至少 1 条正向与 1 条异常用例。
2. **规范一致性**：CommonMark/GFM 规范用例通过率达到约定阈值。
3. **输入法测试**：不同系统、不同浏览器、不同输入法的组合矩阵。
4. **兼容与回归**：浏览器矩阵自动化回归，视觉回归对比渲染差异。
5. **性能压测**：不同文档规模下的渲染与输入延迟基线。
6. **安全测试**：XSS 注入用例、恶意 HTML 与链接用例。
7. **验收门槛**：P0 需求 100% 通过；P1 需求 ≥ 90% 通过；无 P0/P1 级阻断缺陷。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 输入法与 contenteditable 兼容问题 | 丢字、光标跳动，严重影响体验 | 选用成熟内核；建立输入法测试矩阵；组合输入期间屏蔽转换 |
| 往返保真不足导致文件被无故改写 | 版本管理噪声、用户信任受损 | 保留原始风格；未修改区域保持原文；提供差异预览 |
| Markdown 方言差异（CommonMark/GFM/各平台扩展） | 导入导出渲染不一致 | 明确基线与扩展开关；提供降级导出与兼容提示 |
| 大文档性能 | 卡顿、内存占用高 | 虚拟化、增量解析、懒加载重型组件 |
| HTML 与插件带来的安全风险 | XSS、数据泄露 | 白名单净化、CSP、插件沙箱 |
| 协同与 Markdown 文本的一致性 | 合并冲突导致结构错乱 | 在文档模型层协同；块级合并；序列化后校验 |
